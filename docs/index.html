Core Capabilities

Built for unattended reliability, not brittle scripts.

Every rule — schedules, session checks, PID locks, and TikTok selectors — lives in a single shared TypeScript core used identically by the Electron app and the CLI.

One Shared TypeScript Engine

Desktop and CLI both import @tiktok-uploader/core. All TikTok URLs, waits, and DOM locators live in one file (selectors.ts), so a TikTok UI update is a single-file fix.

Real Browser Auth

Drives your installed Brave, Chrome, or Edge via Playwright's launchPersistentContext. Native UA/TLS fingerprint, persistent session storage, plus Netscape cookies.txt import/export.

Multi-Account + PID Lock Safety

Each account owns an isolated profile guarded by account.lock (stale PIDs are reclaimed). Different accounts run in parallel; colliding runs on the same account exit cleanly with code 4.

Headless + Failure Screenshots

Runs headless by default, failing fast with exit code 3 on captcha challenges and saving full-page screenshots to failures/*.png. Toggle Show browser or --headed anytime.

Smart Bulk Scheduling

Enforces TikTok's 5-minute grid, 20+ minute lead time, and 10-day (or 30-day Studio) horizon. Supports per-slot random jitter and quiet-hours windows that wrap cleanly across days.

Crash-Safe Persisted Queue

Every row and status persists to queue.json while Electron holds a powerSaveBlocker during runs. Restarting never loses progress — click Retry Failed or run queue retry-failed.

Two Interfaces, One Profile

Work visually in the Desktop App or automate with tiktok-up.

A sign-in in either interface is immediately active in both. Use the GUI to curate captions and inspect failures, or drive headless batches from cron.

  1. 01

    Pick or Add Account & Sign In

    Select an account or click Add Account. If the status chip shows Expired, click Sign In to authenticate once in your real browser window (or import a Netscape cookies.txt).

  2. 02

    Drop Videos or a Folder

    Use Add Videos, Add Folder, or drag files and directories directly onto the window. Supported formats include mp4, mov, webm, mkv, and more.

  3. 03

    Review Sidecar Captions & Flags

    Captions preload from matching <video>.txt sidecars (or leave empty/edit inline, with a 150-char feed warning and 2,200-char limit). Toggle visibility, Draft, AI label, Comment, Duet, and Stitch per row.

  4. 04

    Bulk Schedule

    Set a start time, interval (e.g. 12h, 1d), optional jitter (15m), and allowed posting window (09:00-21:00). Drafts and private rows are skipped automatically; every row stays editable afterward.

  5. 05

    Confirm & Run Headless

    Click Run to review the pre-run summary (account, video count, schedule span, empty captions). Batches execute headless by default unless Show browser is toggled on.

  6. 06

    Live Logs, Screenshots & Retry

    Monitor stage updates in the collapsible log drawer (with one-click Copy). Failed rows link straight to full-page failure screenshots, and Retry Failed requeues only what failed.

Deterministic CLI Exit Codes
Code Meaning
0 All jobs succeeded (or dry run passed)
1 Unexpected runtime error
2 Invalid arguments, missing files, schedule or caption validation
3 Not signed in, session expired, or captcha challenge
4 Account locked by another process (CLI vs. desktop)
5 Partial failure (some succeeded, some failed)
6 All jobs failed

    Architecture & Shared Data

    Clean boundaries, zero duplicated logic.

    The React renderer never touches the filesystem, profiles, or cookies. Everything flows through one shared engine and one OS data directory.

    packages/desktop Desktop Renderer (React) Pure view via preload window.api
    packages/cli CLI (Commander) tiktok-up · TTY & --json NDJSON
    packages/core @tiktok-uploader/core Profiles · PID Locks · Schedules · Queue · selectors.ts
    playwright-core Installed Browser CHROME_PATH → Brave → Chrome → Edge

    Shared <dataDir> Layout

    <dataDir>/                      # TIKTOK_UPLOADER_HOME overrides
  settings.json                 # browserPath, maxScheduleDays, theme
  accounts.json                 # registered accounts & labels
  profiles/<accountId>/
    browser-profile/            # persistent Chromium userDataDir
    cookies.txt                 # optional Netscape fallback (0600)
    queue.json                  # persisted job rows & statuses
    account.lock                # PID lockfile (reclaimed if stale)
    failures/                   # full-page screenshots on failure
    Default Data Directory by OS (overridden by TIKTOK_UPLOADER_HOME)
    Platform Path
    macOS ~/Library/Application Support/tiktok-uploader
    Windows %APPDATA%\tiktok-uploader
    Linux $XDG_CONFIG_HOME/tiktok-uploader (or ~/.config/tiktok-uploader)

    Quick Start

    Run from source in under two minutes.

    Requires Node.js 20+ and an existing installation of Chrome, Edge, or Brave on macOS, Windows, or Linux.

    Run or Package Desktop App

    # Launch Electron in development mode
npm run dev:desktop

# Build dmg / nsis / AppImage + deb for the host OS
npm run dist:desktop

    Frequently Asked Questions

    Why doesn't it need TikTok API keys?

    Instead of requiring approved TikTok Content Posting API credentials, TikTok Uploader automates TikTok's creator upload page directly inside your real installed Chromium browser (Chrome, Edge, or Brave) using Playwright's persistent browser context.

    Are my login cookies safe?

    Yes. Everything stays local inside your OS data directory (or TIKTOK_UPLOADER_HOME). Each account gets an isolated browser-profile/ directory created with 0700 permissions on POSIX, and optional cookies.txt exports are written with 0600 permissions. Nothing is sent to third-party servers.

    What happens when TikTok changes its upload page?

    Run tiktok-up doctor --account main first to verify your data directory, browser launch, session validity, and the upload page's root selector. Every TikTok URL, wait timeout, and DOM locator is isolated in packages/core/src/selectors.ts so updates are a single-file fix.

    Can cron and the desktop app run at the same time?

    Yes across different accounts — different accounts run in parallel without conflict. For the same account, account.lock prevents two Chromium processes from corrupting the profile: the second process exits cleanly with code 4 (or shows a Locked by CLI chip in the desktop UI). Stale PID locks are automatically reclaimed.

    Why can't I schedule drafts or private videos?

    TikTok only permits scheduling on public or friends-only posts — drafts and private ("Only me") uploads cannot be scheduled on the platform. Both the desktop Bulk Schedule dialog and the CLI enforce this upfront so invalid jobs never fail mid-upload.
